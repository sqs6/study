## 0. 一句话结论

> **单片机** = 一颗"把 CPU、内存、外设全塞进去、能独立跑程序的小芯片"（MCU）。
> **ESP32** = 乐鑫造的"**自带 Wi-Fi + 蓝牙**"的单片机，便宜、资料多、IoT 设备的主力芯。
> **对网安的意义**：它既是**最好下手的攻击面**（大量智能家居直接裸奔），也是**最好的学习硬件**——让你在真实硬件上把 C、内存、协议、密码学、固件逆向串成一条线。

## 1. 单片机：把一台电脑缩进一颗芯片

### 1.1 定义与组成

**单片机（MCU, Micro Controller Unit）**：把 CPU、存储器、时钟、外设全部集成到**一颗芯片**上，配上电源就能独立运行的计算单元。

对比电脑：电脑 = CPU（很贵很慢地跑通用程序）+ 独立主板上的内存/显卡/网卡；单片机 = 这些**全在一颗 5 块钱的芯片里**，主频低（几十~几百 MHz），但足够做"读传感器、控电机、连 Wi-Fi 上传数据"。

| 模块 | 作用 | 你在 C 里怎么见到它 |
|---|---|---|
| **CPU 内核** | 执行指令 | ARM Cortex-M / RISC-V / Xtensa |
| **Flash / ROM** | 存固件（掉电不丢） | 相当于"代码只读区" |
| **SRAM / RAM** | 运行时数据（掉电即丢） | 你学的全局变量/栈/堆就在这儿 |
| **时钟** | 心跳，决定执行速度 | 复位后靠它起步 |
| **GPIO** | 通用输入输出（点灯、按键） | `GPIO_write()` |
| **UART** | 串口（打印调试信息） | `printf` 重定向到串口 |
| **I2C / SPI** | 接传感器、屏幕、SD 卡 | 两条线/四条线的高速总线 |
| **ADC / DAC** | 模拟↔数字转换（读电压、出声） | 采样、波形输出 |
| **定时器 / PWM** | 精确定时、LEDC 调亮度、舵机角度 | 电机/舵机控制 |
| **看门狗 WDT** | 程序跑飞自动复位 | 可靠性兜底 |
| **调试口 JTAG/SWD** | **外部单步调试、断点** | ⭐ 安全研究的关键入口 |
| **加密引擎** | 硬件 AES/SHA/RNG | 安全启动、固件加密靠它 |

### 1.2 它和 CPU / SoC / FPGA 的区别

| | 单片机 MCU | CPU | SoC | FPGA |
|---|---|---|---|---|
| 本质 | CPU+存储+外设集成 | 只有运算核心 | 手机级芯片（CPU/GPU/NPU/基带） | 可重构逻辑电路 |
| 跑什么 | 裸机 / RTOS | 操作系统 | Android/Linux | 数字电路 |
| 功耗 | µW ~ mW | W 级 | W 级 | mW ~ W |
| 例子 | ESP32、STM32、51 | x86/ARM CPU | 麒麟/骁龙 | FPGA 开发板 |

**"为什么 IoT 设备爱用 MCU 而不是 Linux 板"**：成本（一颗 MCU 几块钱 vs 树莓派几百）、功耗（电池供电要几个月）、实时性（没有内核调度抖动）、启动速度（毫秒级）。

### 1.3 核心特征

1. **实时性**：没有 OS 抢占，中断响应确定（μs 级）
2. **低功耗**：深度睡眠可达 µA 级，靠电池工作数月
3. **体积小**：几 mm² 级
4. **成本低**：单芯片 BOM 成本几元
5. **裸机可控**：没有操作系统这层黑盒，**硬件行为完全可预测** —— 这对做安全研究是优点

### 1.4 常见架构与厂商

| 架构 | 特点 | 代表 |
|---|---|---|
| **ARM Cortex-M** | 生态最广（STM32 全系） | STM32F1/F4/H7、G32、GD32、CH32 |
| **RISC-V** | 开源指令集，新生代 | ESP32-C3/C6/H2、GD32V、Milk-V |
| **Xtensa (ESP)** | 乐鑫自研，带向量指令 | ESP32 / S2 / S3 |
| **AVR** | 经典 8 位 | Arduino Uno |
| **8051** | 最老，国内教材常见 | STC89C52 |

> 💡 **对你的价值**：你在 `D:\Study\C\week01` 做的"类型表与 sizeof 实验"、指针、内存布局，**在 MCU 上全部有实物对应**——`sizeof` 在这里就是"这块 RAM 还剩多少"。

### 1.5 开发流程（一条完整链路）

```
  写代码(.c)  ──交叉编译──▶  固件(.elf/.bin)  ──烧录──▶  芯片 Flash
      ▲                                                    │
      └──────────── 调试器(JTAG/SWD) ◀── 单步/断点/读内存 ───┘
```

关键概念：

- **交叉编译**：在 x86 Windows 上编出给 ARM/RISC-V 跑的目标代码，工具链前缀如 `xtensa-esp32-elf-gcc`、`riscv32-esp-elf-gcc`
- **烧录**：通过 **UART 串口**（最常见）或 **USB/JTAG** 把固件写进 Flash
- **调试**：JTAG/SWD 让你能**在目标芯片上打断点、看寄存器和内存**——这和在 VS 里调 C 程序是一回事，只是换成了硬件

> ⚠️ **安全视角**：JTAG 口能读出整片 Flash。量产设备如果不烧 eFuse 关掉 JTAG，等于**把固件和密钥直接送给攻击者**。这是硬件安全的经典第一课。

### 1.6 裸机 vs RTOS

| | 裸机（bare-metal） | RTOS（如 FreeRTOS） |
|---|---|---|
| 结构 | `while(1)` + 中断 | 多任务 + 调度器 |
| 适合 | 功能简单 | 多路并发（Wi-Fi + 传感器 + 显示） |
| 风险 | 中断与主循环竞争 | 竞态、优先级反转、死锁 |

**ESP-IDF 内置 FreeRTOS**（ESP32 原生双核，一个核跑协议栈、一个跑你的任务，或用 `task` 绑核）。

## 2. ESP32：自带 Wi-Fi 和蓝牙的单片机

### 2.1 定位与历史

- **厂商**：乐鑫科技 Espressif Systems（上海，2016 年发布 ESP32）
- **爆火原因**：**性价比 + 开源 + 资料多**。同期同类芯片要么贵、要么资料封闭；ESP32 提供了官方 SDK、Wi-Fi/BT 协议栈、加密引擎，且资料公开 → 直接催生了 IoT 黑客生态（后面 3.5 节讲）
- **对比 ESP8266**：更早、更便宜、只有 Wi-Fi、资料少（已被 ESP32 全面替代）
- **它不是**：树派（那是 Linux 电脑）、Arduino（那是板子+生态）

### 2.2 型号家族

| 型号 | 内核 | 主频 | SRAM | 无线 | 特色 | 适合 |
|---|---|---|---|---|---|---|
| **ESP32** | 双核 Xtensa LX6 | 240 MHz | 520 KB | Wi-Fi b/g/n + BT 4.2 | 经典款，资料最多 | 学习、通用 |
| ESP32-S2 | 单核 Xtensa LX7 | 240 MHz | 320 KB | Wi-Fi（**无蓝牙**） | GPIO 多、USB OTG | 无蓝牙需求、Wi-Fi 配网 |
| **ESP32-S3** | 双核 Xtensa LX7 | 240 MHz | 512 KB | Wi-Fi + **BLE 5.0** | **向量指令**、USB OTG、摄像头接口 | AI 边缘、蓝牙、USB 直连 |
| ESP32-C3 | 单核 RISC-V | 160 MHz | 400 KB | Wi-Fi + BLE 5.0 | 便宜、RISC-V | 低成本 IoT |
| ESP32-C6 | RISC-V | 160 MHz | 512 KB | **Wi-Fi 6** + BLE 5.3 + **802.15.4** | 协议最全 | Matter/Thread/Zigbee |
| ESP32-H2 | RISC-V | 96 MHz | 320 KB | **802.15.4** + BLE 5.3（**无 Wi-Fi**） | 低功耗无线 | Thread/Zigbee 节点 |

> ⚠️ **买板子看丝印**：要 BLE + 跑小模型 → **S3**；要便宜试水 → **C3**；跟着最多教程走 → 原版 **ESP32**。

### 2.3 内部结构

```
┌─────────────────────────────────────────────┐
│  双核 CPU (Xtensa / RISC-V)  ← 跑你的代码      │
│  ┌────────┐  ┌────────┐                      │
│  │ ULP 协处理器 │  │ 硬件加密引擎 │  ← 安全启动/加密 │
│  └────────┘  └────────┘                      │
│  SRAM (几百 KB)          Flash (4/8/16 MB)   │
├─────────────────────────────────────────────┤
│  Wi-Fi 射频 + 协议栈(lwIP)   蓝牙(BLE/BR/EDR) │
├─────────────────────────────────────────────┤
│  GPIO / UART / I2C / SPI / I2S / ADC / DAC   │
│  定时器 / LEDC(PWM) / RMT / 触摸 / 温度传感器   │
└─────────────────────────────────────────────┘
```

要点：

- **ULP 协处理器**：主 CPU 睡眠时它还能跑代码（读传感器、唤醒主核）→ 实现"月度上报一次"的低功耗节点
- **硬件加密引擎**：AES/SHA/椭圆曲线/RNG 有专用硬件指令 → 既快又不占用 CPU
- **Flash 里存固件**：可以通过 eFuse 锁死（一次性，不可逆）

### 2.4 外设清单

| 外设 | 典型用途 | 安全视角 |
|---|---|---|
| **GPIO** | 点灯、按键、继电器 | 继电器控制 = 物理攻击面 |
| **UART** | 调试日志、AT 指令、连接其他模块 | **设备调试输出常泄露密钥/口令**；UART 也能当"输入设备"被劫持 |
| **I2C / SPI** | 传感器、OLED、E-paper | 总线上能嗅探到明文数据 |
| **I2S** | 麦克风、音频 | 语音唤醒、音频侧信道 |
| **ADC** | 读电压/温度 | **电源侧信道**（功耗曲线泄露密钥） |
| **DAC** | 输出波形 | 信号注入攻击（glitching） |
| **LEDC(PWM)** | 调光、舵机、载波 | **载波注入**（RFID 读写器） |
| **RMT** | 红外遥控 | 无 |
| **触摸/电容按键** | 手势 | 无 |
| **TWAI/CAN** | 汽车总线 | ⭐ **车联网安全**的入口 |

### 2.5 无线能力

| 能力 | 说明 | 安全意义 |
|---|---|---|
| Wi-Fi **STA** | 连路由器 | 常规联网 |
| Wi-Fi **AP** | 自己做热点 | ⭐ **"Evil AP"**：伪造热点劫持设备/手机流量 |
| Wi-Fi **Sniffer** | 抓周边 802.11 帧 | ⭐ **无线审计**、研究 WPA 握手 |
| **ESP-MESH** | 多节点自组网 | 攻击面=整个 mesh |
| **BLE** | 蓝牙低功耗 | ⭐ 蓝牙嗅探、**BLE 键盘注入**（BlueDucky 类） |
| 经典蓝牙 BR/EDR | 老蓝牙 | 配对 weaknesses |
| **Wi-Fi + BT 共存** | 同时开 | 射频共存 = 干扰/DoS 研究点 |

### 2.6 功耗档位

| 模式 | 典型电流（3.3V） | 适用 |
|---|---|---|
| Active（Wi-Fi 发送） | 峰值 ~180–240 mA | 联网工作 |
| Modem-sleep | ~3–20 mA | Wi-Fi 常连 |
| Light-sleep | ~0.8 mA | 定时唤醒 |
| **Deep-sleep** | **~10 µA** | 电池节点（几个月级） |
| Shutdown | ~1 µA | 最低 |

> 💡 你的 `D:\Study` 里如果做一个"宿舍环境监控"，用 **Deep-sleep + 每 10 分钟唤醒上报** → 一节 2000mAh 电池能撑好几个月。**这就是 MCU 存在的意义**，也是它和树莓派的本质区别。

### 2.7 安全机制（重点）

这是"网安人必须懂"的部分：

| 机制 | 作用 | **默认状态** |
|---|---|---|
| **Secure Boot** | 只允许运行签名过的固件，防止固件被替换 | ❌ **默认关闭** |
| **Flash Encryption** | 加密 Flash 内容，防止被 dump 出固件/密钥 | ❌ **默认关闭** |
| **eFuse** | 一次性熔丝，永久生效（烧了就回不去） | 未烧 |
| **RDP（Read Protect）** | 禁止外部读 Flash | 未开 |
| **JTAG 禁用** | 物理关掉调试口 | 未烧 |
| **Secure Element / 密钥分区** | 存密钥，防提取 | 需配置 |
| **硬件 RNG** | 真随机数 | ✅ 硬件自带 |

> ⚠️ **记住这条**：**这些保护默认全是关的**。所以你手里的开发板是"完全透明"的——这对你研究是**好事**（可以随便读固件分析），对量产是**事故**（必须自己配起来）。
>
> 这也是"IoT 设备最容易被攻破"的根本原因之一：**厂家为了省事，全都没开。**

**Windows 上的关键坑**

1. **WSL2 要开虚拟化**；`wsl --install` 后可能需要重启
2. **USB 串口驱动**：`CH340` / `CP2102` / `FTDI` 三选一，Win11 多数自带，Win10 常要手装
3. **ESP32-S3 / C3 支持原生 USB**（USB-Serial-JTAG），插上就是串口，但要用对 USB 口（标 `USB` 的那个）
4. **供电**：别用电脑 USB 口带大负载（如 5V 舵机 + Wi-Fi 发射），容易掉电复位 → 用独立电源
5. **Flash 电压 3.3V**，别接 5V 信号

## 3. 单片机在网络安全中的角色

### 3.1 攻击面：IoT 是最好下手的一类目标

IoT 设备占全网设备数量的**大部分**，且安全基线极低。典型问题：

| 问题 | 说明 | 后果 |
|---|---|---|
| **默认口令** | admin/admin、root/root 不改 | 直接沦陷 |
| **弱口令 + 开放管理端口** | Telnet/23、SSH/22、HTTP 管理口 | 批量扫描 → 僵尸网络 |
| **调试口未关** | JTAG/UART 暴露在设备外壳上 | 固件、密钥、算法被直接读走 |
| **固件明文** | Flash 未加密 | 提取固件 → 逆向 → 找漏洞 |
| **OTA 无签名验证** | 升级包不验签 | 中间人刷后门 |
| **云端凭据硬编码** | 设备里写死云账号 | 泄露后能控制整个设备群 |
| **依赖过期** | 第三方库/固件不更新 | 已知 CVE 直接利用 |
| **供应链投毒** | 出厂固件被植入 | 侧信道/后门 |

### 3.2 真实世界的经典案例（类型级）

> 以下只列**公开广为报道的类型**，用于理解攻击链，不涉及具体在位设备。

1. **Mirai 及其变种（2016 至今）**
   - 原理：扫描公网 Telnet/SSH → 用**出厂默认口令字典**登录 → 下载并执行对应架构的恶意载荷 → 加入僵尸网络发起 DDoS
   - 影响：第一次让"物联网设备"成为大规模 DDoS 的主力军种；源码泄露后衍生出数百个变种
   - **教学价值**：完整演示了"弱口令 + 默认配置 + 可执行下载链"的攻击模型

2. **路由器/摄像头 RCE**
   - 大量低端设备的 Web 管理接口存在**未授权命令注入**
   - Realtek SDK 的 UPnP SOAP 处理不当 → 被大量僵尸网络用来扩散
   - Huawei HG532 的 UPnP 远程代码执行（CVE-2017-17215）是经典公开案例

3. **固件供应链与后门**
   - 出厂固件被植入后门、默认密码后门、隐蔽的远程管理通道

4. **消费级设备"云接管"**
   - 设备与厂商云强绑定 → 云凭据泄露 = 设备群被远程控制（已多次大规模发生）

5. **ESP32 生态自身的风险**
   - 大量"ESP32 智能插座/灯/摄像头"出厂**不带任何加密**，出厂固件公开可下载 → 改固件即量产后门
   - **Pwnagotchi**、**BlueDucky** 等公开项目证明：几十块钱的板子就能做无线攻击平台

### 3.3 防御面：设备该怎么做才安全

| 层面 | 措施 |
|---|---|
| 硬件 | 烧 eFuse 关 JTAG、开 RDP、Flash 加密、用 Secure Element 存密钥 |
| 固件 | **Secure Boot + OTA 签名验证**、关闭不需要的外设、最小化依赖 |
| 凭据 | **每台设备唯一口令**、存哈希不存明文、支持强制改密 |
| 网络 | 不暴露管理口到公网、禁用 Telnet、mTLS/证书认证 |
| 运维 | OTA 通道加密、漏洞响应机制、可更新的依赖清单 |

### 3.4 ESP32 特有的安全问题清单

| # | 问题 | 原理 | 你能怎么验证 |
|---|---|---|---|
| 1 | **Flash 加密默认关** | `esptool.py read_flash` 直接 dump 整个固件 | 自己板子上 dump 一遍试试 |
| 2 | **Secure Boot 默认关** | 可任意刷入任意固件 | 同上 |
| 3 | **JTAG 默认开** | 插 JTAG 就能单步调试、读内存 | 用 OpenOCD attach 一次 |
| 4 | **Wi-Fi 凭据明文存 NVS** | 读 Flash 就能拿到 SSID/密码 | dump 后 strings 一下 |
| 5 | **UART 日志泄露** | 调试输出里打印了令牌/口令 | 抓串口输出看 |
| 6 | **栈保护 /GS** | 栈溢出检测（cookie） | 故意溢出看崩溃行为 |
| 7 | **栈溢出 / 格式化字符串** | 无 ASLR、栈可执行与否由配置决定 | 构造样本验证缓解是否生效 |
| 8 | **硬编码密钥/证书** | 固件里藏着对称密钥 | strings 固件 |
| 9 | **随机数质量** | 早期型号 RNG 熵源有限 | 统计检验 |
| 10 | **Bootloader 物理接口** | UART 下载模式可重刷 | 理解"物理不可信"假设 |

> 🎯 **这条线的价值**：这 10 条几乎覆盖了"嵌入式安全"的全部基本盘。你在 ESP32 上亲手验证一遍，比看十篇论文都强。

### 3.5 单片机在安全研究中的四个用法

| 用法 | 怎么实现 | 对应能力 |
|---|---|---|
| **① 无线审计/研究** | ESP32 Sniffer 模式抓 802.11 帧；自建 Evil AP 做流量劫持 | 协议分析、无线安全 |
| **② 蓝牙注入** | ESP32-S3 伪装成蓝牙键盘/鼠标注入按键 | 无线协议实现、输入注入 |
| **③ 攻击平台** | Pwnagotchi 类：ESP32 + 电池 + 屏幕 = 便携 Wi-Fi 审计/钓鱼/AP 平台 | 系统集成、无线安全 |

## 7. 踩坑清单

> 每一条都是"会让你卡住半天"的坑，提前知道能省时间。

### 硬件/接线
- [ ] **供电不稳** → Wi-Fi 一发就掉线复位。用外部电源，别用电脑 USB 带舵机
- [ ] **3.3V 电平** → ESP32 是 3.3V 逻辑，接 5V 信号会烧
- [ ] **串口驱动** → CH340/CP2102/FTDI 对应驱动；Win11 常自带
- [ ] **插错口** → S3/C3 有两个 USB 口（原生 USB vs UART），刷固件要用对
- [ ] **BOOT 键** → 烧录时按住 BOOT 再按 EN（老板子需要）

### 软件/工具链
- [ ] **WSL2 没开虚拟化** → `wsl --install` 后重启；权限不足要管理员
- [ ] **ESP-IDF 环境变量** → 每次开终端先跑 `idf.py` 的环境脚本（Windows 是 `export.ps1`）
- [ ] **Python 环境冲突** → 用 ESP-IDF 自带的虚拟环境，别污染系统 Python
- [ ] **idf.py 找不到** → 没 export 环境
- [ ] **串口被占用** → 关掉其他串口软件（VS Code 串口、Arduino IDE）

### 思维/习惯
- [ ] **别一上来就做复杂项目** → 先点灯、先串口打印
- [ ] **每个实验建一个分支** → `git switch -c exp/xxx`，实验失败一键回退
- [ ] **实验写成笔记** → 进 `D:\Study\notes\` 或 `articles`
- [ ] **注意时间投入** → 主线优先，ESP32 是支线，别让支线吃掉主线时间

## 8. 常见坑与排错

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 烧录报 `Failed to connect to ESP32` | 串口号错 / 驱动缺失 / 没按 BOOT | 换 USB 口、按住 BOOT、装驱动 |
| 程序跑起来反复重启 | 供电不足 / 栈溢出 | 换电源；看复位日志 |
| 串口输出乱码 | 波特率不对（常 115200） | 对齐波特率；确认是 USB-TTL 口 |
| Wi-Fi 连不上 | 2.4G 频段 / 密码 / 隐藏 SSID | 确认是 2.4G |
| `idf.py: command not found` | 没 export 环境 | 跑 ESP-IDF 的环境脚本 |
| dump 固件是乱码 | Flash 加密已开 | 需要在 bootloader 阶段用加密流程读 |
| 逻辑分析仪抓不到 | 采样率不够 / 地线没接 / 通道接错 | 共地、降低速率、换通道 |
| JTAG 连不上 | 烧了 eFuse 禁用 JTAG | **永久不可恢复**，只能靠 UART/OTA |

## 11. 一页速查

```
【术语】
MCU 单片机 | SoC 系统级芯片 | RTOS 实时系统 | JTAG/SWD 调试口 | eFuse 一次性熔丝
Secure Boot 安全启动 | Flash Encryption 闪存加密 | RDP 读保护 | ULP 超低功耗协处理器
Sniffer 嗅探模式 | Evil AP 伪造热点 | IAT 导入地址表 | U-Boot 引导程序

【ESP32 家族】
ESP32 双核Xtensa+BT | S2 无蓝牙 | S3 双核+向量指令+BLE5 | C3 单核RISC-V | C6 WiFi6+802.15.4 | H2 仅802.15.4+BLE

【安全能力 ↔ 硬件手段】
固件逆向    → esptool dump + Ghidra
栈溢出研究  → 无 OS、无 ASLR 反而好复现
无线研究    → Sniffer / Evil AP / BLE 注入
侧信道      → ADC 测功耗 / glitching
协议分析    → 逻辑分析仪 + UART 嗅探
车辆安全    → CAN/TWAI 总线
```
